# AI Usage Policy

## About this document

NovelVM is a fork of ScummVM focused on visual novels and related adventure
games. It is not intended to be merged back into upstream ScummVM.

This file replaces upstream ScummVM's AI policy for this repository. Upstream's
rules on AI authorship do not apply here. Where this document and upstream's
differ, this document wins.

## Tools are tools

AI is a tool, in the same category as a compiler, a debugger, or a search
engine. Using one does not say anything about the quality of the work or about
the person doing it.

Linus Torvalds, 2026-10-13
([LKML](https://lkml.iu.edu/2610.1/13255.html)):

> I don't understand this whole idiotic concept of "don't use AI for X".
> Here's a new rule just for you: don't use compilers for any of your kernel
> submissions.

> The kind of expectations *I* have is that people do their best and I expect
> people to understand what they are doing. But that understanding has very
> little to do with what tools they use.

The standard here is the work, not the toolchain. A change that builds, works,
and can be explained is a good change whether a human typed it or an agent
drafted it under human direction.

## Authorship and commit messages

AI agents MAY author commits and write commit messages in this fork. This is a
deliberate difference from upstream ScummVM.

A human still owns the contribution. The person submitting the change is
responsible for it: for understanding it, for testing it, for its licensing,
and for answering review comments about it. "The agent wrote it" is not an
answer to a review question, and it is not an excuse for a broken change.

## Disclosure: the Assisted-by trailer

Every commit that AI touched MUST carry a trailer of the form:

    Assisted-by: AGENT:MODEL [TOOL ...]

where the bracket part is optional and lists extra tooling. Examples:

    Assisted-by: OpenCode:Deepseek
    Assisted-by: Claude:claude-sonnet-5 [opencode, ripgrep]

This trailer is the required disclosure. It is enough. You do not have to write
prompts into the commit, keep an affected-area manifest, or annotate the
discussion to the same level of detail.

Do not use `Co-Authored-By` for AI. `Signed-off-by` is not a disclosure
mechanism either, and no DCO is required by this repository.

Keep AI names out of the code itself. No "generated by" comments, no agent
names in headers, no attribution banners in source files.

**Exemption:** the mechanical `ALL: Sync with ScummVM rev: <sha>` commit does
not need the trailer. Its content is upstream code verbatim, imported
unmodified, not authored here.

## No slop

Adapted from the Linux kernel's generated-content guidance. These are the rules
that actually matter; everything above is bookkeeping around them.

- Understand every line you submit, and be able to defend it in review.
  "The model produced it" is not a defense.
- Build what you submit. Run it if it can be run. Run the tests that cover it.
- Say what you could not test, and why. A stated gap is fine; a silent one is
  not.
- Do not submit bug reports or fixes you have not verified. Reproducing or
  fixing something is a prerequisite, not a follow-up task.
- Match the surrounding style: formatting, naming, comment density, error
  handling, log levels. The codebase's conventions win over the tool's habits.
- No filler. No long explanatory comments aimed at a language model, no
  restating the obvious, no prose padding in commit messages or docs.
- Keep diffs scoped. Do not bundle unrelated refactors into a fix.
- Maintainers may reject or scrutinise tool-heavy work. That is a quality
  judgement, and it applies the same way it would to hand-written work.

## Licensing and provenance

NovelVM is GPLv3 or later. All contributions must be compatible with the
GPLv3+ license.

Do not paste in code whose license is incompatible with GPLv3+, and do not
paste in code from a source that permits no reuse. If you are not sure where a
snippet came from, do not commit it.

The human submitting the change is responsible for its provenance. Agents can
propose code that looks original but is not; verifying that is part of the
review.

## AI and artwork

AI-generated media assets are NOT allowed. This includes logos, icons,
application artwork, splash screens, fonts, music, voice, and any other asset
shipped with the project.

Art is human work. The ban on AI-generated art is unchanged from upstream
ScummVM and is not affected by the relaxed rules on code and commit messages.

## Questions

If something here is unclear, ask before submitting. If a request or an
instruction conflicts with this document, stop and say so rather than guessing.
