# Updating NovelVM from upstream ScummVM

NovelVM is a fork of [ScummVM](https://www.scummvm.org/) focused on visual
novel games. This document describes the repository layout, the update
workflow, and the supported build commands.

## Remotes

| Remote    | Purpose                                        |
|-----------|------------------------------------------------|
| `origin`  | The NovelVM fork (`monyarm/NovelVM`).          |
| `scummvm` | Real upstream ScummVM (read-only; never pushed to, never rewritten). |

If `scummvm` is missing (e.g. in a fresh clone), `./rebase.sh` adds it
automatically using the URL recorded in `.novelvm-update.conf`.

## Architecture

Git cannot check out a path under a different name, and rename detection is
only a heuristic — so the update workflow makes upstream path names match
the fork's convention *before* any rebase:

1. `scummvm/master` is fetched normally into `refs/remotes/scummvm/master`.
   This ref is **never** modified.
2. A local ref `refs/rewrites/scummvm-master` is generated by rewriting the
   **full upstream history**: every path component containing `scummvm`
   (case-insensitively) is renamed to `novelvm` at whichever commit
   introduced it, preserving per-character casing:
   `ScummVMActivity.java -> NovelVMActivity.java`,
   `SCUMMVM.BIN -> NOVELVM.BIN`, etc. Rewriting full history (rather than a
   range) guarantees every rewritten tree is internally consistent — no
   path survives under its old name. The rewrite only touches Git paths —
   never file contents. Copyright headers, identifiers, documentation text,
   and branding inside files are deliberately left alone.
3. master is rebased onto the rewritten ref.

The rewrite is deterministic: identical upstream input produces identical
commits, so re-running an update with no new upstream changes regenerates
byte-identical history and produces no churn.

Tooling: `devtools/rewrite-upstream-paths.py`

- `rewrite <base>..<tip> <dst-ref>` — stream rewrite via
  `git fast-export --no-data` / `git fast-import`.
- `validate <tree-ish>` — walks a tree applying the rename rule and aborts
  if two source paths map to one destination, or if a renamed path would
  overwrite an existing file with different content. Run against
  `refs/rewrites/scummvm-master^{tree}` after each rewrite.

Configuration lives in `.novelvm-update.conf` (remote names/URLs, the
historical merge-base `REWRITE_BASE`, protected engines).

## Engine filtering

Upstream game-engine directories are kept **in Git history** but hidden
from the working tree through non-cone sparse checkout
(`.git/info/sparse-checkout`, regenerated by `rebase.sh`). This avoids
committing deletions that would conflict forever with future upstream
engine changes.

The shared `engines/` framework files (engine.cpp, engine.h,
metaengine.h, ...) always remain available, as do the protected NovelVM
engines listed in `.novelvm-update.conf`:

```
bibleblack
koihime_doki
smt
```

Configure therefore only ever sees the shared framework plus protected
engines.

## Update workflow

Prerequisites: clean working tree (no staged or modified tracked files),
run from the repository root, `python3` on PATH.

```sh
./rebase.sh            # fetch + rewrite + rebase + filter + validate
./rebase.sh --continue # resume after manually resolving conflicts
```

Behavior:

- Refuses to run with uncommitted changes.
- Verifies the `scummvm` remote URL.
- Prints the upstream commit before and after the update.
- Rebases onto `refs/rewrites/scommvm-master` (see config) with no global
  `-X ours` / `-X theirs` strategy. Delete/modify conflicts under
  unprotected `engines/<name>/` are auto-resolved by keeping the upstream
  side; every other conflict stops the script without touching your work.
- Validates the rewritten tree for path-mapping collisions and checks that
  all protected engines exist both in the commit and on disk.
- Is idempotent: a second run with no upstream changes does nothing.

## Building

Only the protected engines are built:

```sh
./configure --disable-all-engines --enable-engine=bibleblack,koihime_doki,smt
make -j$(nproc)
```

Build a single engine by passing just its name to `--enable-engine`.

After an update, build from a clean state:

```sh
make distclean
./configure --disable-all-engines --enable-engine=bibleblack,koihime_doki,smt
make -j$(nproc)
```

## Notes

- The Android port's `NovelVMActivity.java` intentionally still references
  `scummvm.ini` paths internally: that logic migrates existing ScummVM
  installs' user data and must keep looking for the old file names.
- Packaging files under `dists/` exist in both `scummvm.*` and `novelvm.*`
  variants where the fork had not finished renaming them; upstream updates
  land at their rewritten (`novelvm.*`) paths and surface as normal,
  reviewable add/add conflicts when both sides changed.
